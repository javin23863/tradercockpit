Docs / exact reference

Find the exact answer, not a marketing paragraph.

Docs are reserved for precise, verified product reference. Research education belongs in Learn and Methods; task instructions belong in How-Tos. That separation keeps in-app help direct and predictable.

This public documentation area will only describe product behavior that is approved for public disclosure. Research concepts may exist on the site before a matching product capability is publicly verified.
Documentation map

Three kinds of answer.

Users should not have to guess whether they need a definition, a workflow, or a control reference.

Reference

What does this control mean?

Exact field names, allowed values, behavior, validation, errors, defaults, and related help IDs—only after the behavior is verified for public documentation.

How-To

How do I accomplish this task?

Goal-oriented steps, prerequisites, expected results, common mistakes, troubleshooting, and optional video.

Contextual help

Stable help IDs, exact deep links.

Instead of sending a user from an in-app “What is this?” link to a generic documentation homepage, the site exposes a versioned registry of public-safe knowledge IDs. A future application integration can map a UI context to one of those IDs and open the exact explanation.

Example: research.monte-carlo resolves to the Monte Carlo section of Research Lab. The public registry does not contain unreleased controls, private application routes, backend names, or internal implementation details.
