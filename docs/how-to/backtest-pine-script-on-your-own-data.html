How to Backtest Pine Script on Your Own Data

Put your bars on a chart, open the Pine Script panel, paste the strategy and press Add to chart. It runs on that chart’s bars, and the Strategy Tester under the chart lists every trade.

ChartsPine v4 to v6Strategy Tester
What you need

A Pine strategy and the bars to run it on

  • A Pine script that calls strategy(). Indicators run too; they draw on the chart.
  • A chart of the bars you want: a price file you imported (a TradingView chart export works), history from a connection, or a live Coinbase or Kraken market.
Steps

Bars first, then the script

  1. Put your data on a chart. Import the file in Data organization, save it, and press Open Chart. Or open any market in Charts.
  2. Open the Pine Script panel. Open it from the chart’s side panels, or open Indicators, go to the Pine Script group and press Open editor.
  3. Press New, name the script and paste the code. The two fields are Script name and Pine Script code.
  4. Press Add to chart. The strategy runs on the chart’s bars. On a long history you see progress as a percentage and a count of bars, with a Cancel button.
  5. Read the Strategy Tester under the chart. The header gives Total PnL, Max drawdown, Total trades, Profitable trades and Profit factor. Metrics breaks them down. List of trades has every trade with its signal, price, size, net P&L, excursions and duration.
  6. Download the trades. Columns picks the columns, and Download CSV saves the list in the columns of a TradingView strategy export, so the two line up side by side.
  7. Change an input and run again. The script’s inputs are on the Inputs tab of its settings. After editing the code, press Update on chart.
When it can’t run

What happens when a line can’t run

The script’s own order rules apply as written: order types, pyramiding, commission, slippage, margin and process_orders_on_close. If a line can’t run, nothing is drawn and the panel lists it as “Line N” with the reason.

Three strategy settings are refused because history runs once per bar: calc_on_every_tick, calc_on_order_fills and use_bar_magnifier. The panel names the setting when it stops a script.

Mistakes

Data mistakes that change a Pine result

  • Importing bars with the wrong time zone, so session rules and daily closes fire on the wrong bar.
  • Comparing runs on two data sources and calling the difference a bug. Different bars give different trades.
  • Leaving commission and slippage out of the strategy() line.
  • Expecting fills inside a bar to follow real ticks. They use the bar’s open, high, low and close.
Questions

Questions about running Pine Script here

Which Pine versions run?

Versions 4, 5 and 6, indicators and strategies.

Can I go the other way, from a strategy to Pine?

Yes. Export a Builder strategy as Pine for TradingView.
