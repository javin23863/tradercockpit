How to Backtest a Pine Script Strategy on Your Own Data

A Pine strategy’s result depends on the bars it runs on. Trader Cockpit runs Pine v5 and v6 strategies on the chart’s own bars, so you can test a script on your broker’s history, an export, or live crypto prices.

ChartsPine v5 and v6Strategy Tester
What you need

A script and the bars to run it on.

  • A Pine v5 or v6 script that calls strategy(). Indicators run too; they just draw.
  • A chart of the bars you want: a price file you imported (a TradingView chart export works), history from a connection, or a live Coinbase or Kraken market.
Steps

Bars first, then the script.

  1. Put your data on a chart. Import the file in Data, save it, and press Open Chart. Or open any market in Charts.
  2. Open the Pine Script panel. Press Pine Script in the chart’s right rail, or open Indicators and choose the Pine Script group.
  3. Press New, name the script and paste the code. Script name and Pine Script code are the two fields.
  4. Press Add to chart. The strategy runs on this chart’s closed bars. On a long history you see progress as a percentage and a count of bars, with a Cancel button.
  5. Read the Strategy Tester under the chart. The header gives Total PnL, Max drawdown, Total trades, Profitable trades and Profit factor. Metrics breaks them down. List of trades has every trade with its signal, price, size, net P&L, excursions and duration.
  6. Download the trades. Columns picks the columns, Download CSV saves the list. It comes out in the columns of a TradingView strategy export, so the two line up side by side.
  7. Change an input and run again. The script’s inputs are on the Inputs tab of its settings. Edit the code and press Update on chart to run the new version.
What you should see

Trades on your bars, or a list of what stopped it.

The script’s own order rules apply as written: order types, pyramiding, commission, slippage, margin and process_orders_on_close. If a line can’t run, nothing is drawn and the panel lists each one as “Line N” with a plain reason, so you know what to change.

If the numbers differ from what you saw elsewhere: compare the bars first. Different data means different trades, and that difference is the point of testing on your own.
Mistakes to avoid

Mostly about the data.

  • Importing bars with the wrong time zone. Session rules and daily closes then fire on the wrong bar.
  • Comparing a run on one broker’s bars with a run on another’s and calling the gap a bug.
  • Leaving commission and slippage out of the strategy() line.
  • Expecting fills inside a bar to follow real ticks. Fills inside a bar use its open, high, low and close.
Questions

Short answers.

Which Pine versions run?

Version 5 and version 6, indicators and strategies.

Which strategy settings are refused?

calc_on_every_tick, calc_on_order_fills and use_bar_magnifier. The history runs once per bar. The panel names the setting when it stops a script.

Does the script run on live bars?

Yes. It runs again each time a bar closes, and when you change a setting.

Can I go the other way, from a strategy to Pine?

Yes. Export a Builder strategy as Pine for TradingView.
