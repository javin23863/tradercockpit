How to Walk-Forward Test a Trading Strategy

One in-sample and out-of-sample split is a single exam. Walk-forward sets the exam again and again: fit the settings on a window, trade the window after it, slide forward, repeat. It is the closest a backtest gets to how you would really run a strategy.

What you need

A strategy with settings to re-fit, and long history.

  • A strategy from Builder that has settings worth re-fitting, such as a period or a level.
  • A long saved history. Every run needs its own in-sample window and its own out-of-sample window, with enough trades in each to mean something.
Steps

Turn it on, set the windows, run, read.

  1. Open your workflow in Workflows. Use the copy that built or tested the strategy, so the walk-forward runs on the strategies it kept.
  2. Turn on the walk-forward check. Open the Test strategies step that comes after the checks the strategy already passed, or add one. In its stress tests, turn on Walk-forward optimization. For the wider version, turn on Walk-forward matrix: it repeats the test across many window layouts.
  3. Set the windows. Choose how the windows are measured. As a share: Out-of-sample % and the number of Runs. Or as a length: In-sample days and Out-of-sample days, or the same in bars.
  4. Press Run and confirm. It runs like any other step, on its own.
  5. Open the strategy in Results, then Walk-forward. The card “Walk-forward run” gives the result and a score. The score is the share of checks that passed, and the run passes when at least the stated share of checks pass.
  6. Read the matrix, if you ran one. “Walk-forward matrix result” says how many window layouts passed, names the best block and suggests a setup, with the in-sample and out-of-sample lengths it means.
  7. Change the pass rule only on purpose. Use the suggested checks, or edit them. The screen is worked out again when you do. The result saved with the strategy does not change.
What you should see

A score per run, and whether neighbours agree.

A strategy worth keeping passes at more than one window layout, and layouts next to each other give similar answers. One passing layout surrounded by failures is the walk-forward version of a lucky setting.

Say it this way: “Re-fitted on these windows, it held up on the next ones in most runs.” Not: “it adapts to any market.”
Mistakes to avoid

Walk-forward can be overfit too.

  • Trying window sizes until one passes, then reporting that one. The matrix exists so you can see all of them at once.
  • Out-of-sample windows so short they hold a few trades each.
  • Looking only at the total. Check how many runs were profitable, and how often they flip from profit to loss.
  • Treating walk-forward as the only test. It answers one question. The other checks answer others.
Questions

Short answers.

What is the difference between walk-forward optimization and a walk-forward matrix?

Walk-forward optimization is one layout: one in-sample length, one out-of-sample length, a number of runs. The matrix runs many layouts and shows which ones pass, so you can tell a stable strategy from one that only passes at a single layout.

Can I start a walk-forward from Results?

Walk-forward results come from a workflow and are saved with the strategy. Results shows them and lets you change the pass rule and checks.

What if Results says no walk-forward results are saved?

That strategy never went through a walk-forward check. Turn the check on in its workflow and run it.
